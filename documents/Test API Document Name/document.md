### Overview

This specification describes the messaging requirements for market participants seeking to submit standing orders to Bloomberg Order Book, to execute trades based on prices posted on Bloomberg (Order-Based Model) or to submit inquiries for tradeable prices directly to market makers (Inquiry- Based Model) leveraging the Financial Information eXchange (FIX) ***{{api.version.custom.CustomVersion}}***. For fixed income and equities it also provides a mechanism to obtain a list of dealers with whom the **{{tags.Client}}** is permissioned to trade and is prepared to trade a particular security at the time of sending the inquiry. The interfaces are collectively known as **{{api.name}}**.

### Market Data

Bloomberg does not support market data distribution using this FIX specification. Market data is available via B-PIPE, which is a service managed by Bloomberg Enterprise Solutions. Participants interested in receiving market data should contact their Bloomberg representative - *{{now.date}}*.

### Execution API

ORP allows participants to submit orders and inquiries directly via FIX APIs to Bloomberg for processing. When submitting an order or inquiry, the Bloomberg UUID reference must be a Bloomberg Anywhere (BBA) user.
In the event of a session disconnect all active orders for participants linked to that session will be cancelled immediately by Bloomberg.  
IMPORTANT – The production environment requires all messages to include a valid UUID at the time the message is submitted to Bloomberg. For IRS and CDS orders the user must also be logged in to the Bloomberg Professional service.  
FOR TESTING – The beta environment overrides these checks to make testing easier. PLEASE BE AWARE of the differences between the BETA and PRODUCTION environments.

### Post-Trade

As the final state messages on this platform for IRS and CDS orders filled on the Order Book do not include all trade details, the participant must request Bloomberg to configure an additional separate FIX session to receive post trade ExecutionReport(35=8) messages. These messages will include the client order ID generated by the participant and sent in the NewOrderSingle(35=D) or QuoteResponse(35=AJ) message.  
This is unnecessary for trades filled through Direct Order Routing since those final state messages do contain all trade details.  
ORP IRS and CDS trades can be allocated pre-trade but other asset class trades can only be allocated post-trade. To do post-trade allocation the customer must request Bloomberg to configure the additional FIX session for ExecutionReport(35=8) messages in order to receive post-trade allocation messages and send back responses.

### Protocol

The FIX Protocol was chosen as it is the global messaging standard across the financial industry for pre- trade, trade and post trade communication. The version of the FIX Protocol being supported is version 5.0.
This document is not intended to cover how to and what is needed to implement the FIX Protocol. This document covers the FIX messages and fields that are supported by ORP, describing the message flows and the requirements for integrating with ORP using FIX. The use of the FIX messaging interface allows Bloomberg's clients to achieve straight-through processing by integrating their order or trade management systems directly with Bloomberg's infrastructure.  
Bloomberg's support of FIX builds on the FIX 5.0 Service Pack 2 standard specification, incorporating the latest Extension Packs where needed. There are additional requirements specified in this document that are above the standard specification. Any requirements in the standard specification will also be required by Bloomberg's FIX implementation.
